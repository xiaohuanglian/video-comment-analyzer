# 交付 A：产品诊断报告（基于真实仓库与页面代码）

## 1. 当前产品架构（一句话）

后端：Phase 0–3.6 建成的「单 Orchestrator Agent + 15+4 个受控工具 + 产品隔离文件存储 + REST API」——这条链路是健康的，不需要推倒。
前端：`/growth` 单页，把后端的五类数据对象（机会/任务书/素材/实验/经验）平铺成五个卡片列表，外加一个目标输入框。

## 2. 当前实际操作流程（实测）

用户打开 `/growth` → 选产品 → 输目标 → 点"让 AI 工作" → 看一段文本回答 → 然后被迫在五个并列卡片里自己找"下一步该点哪里"。增长机会和任务书之间、任务书和实验之间没有任何引导串联。

## 3. 五个最主要的产品问题（按严重度）

**P0-1 AI 不理解意图，所有目标都被映射成同一条流水线。**
"帮我找到潜在用户"（用户研究）和"规划下周内容"（内容策划）走的是完全相同的路径：查信号→匹配素材→出选题。原因不在 UI：mock 策略写死了这条路径，且系统提示词没有"目标分类"概念。用户研究类目标的正确产物（用户群体、场景、平台、触达方式、匹配证据、待验证假设）在现有工具里甚至没有对应的输出结构。

**P0-2 Mock 与真实 AI 边界模糊。**
页面默认选 DEMO 产品、默认 Mock 运行，结果区虽有"MOCK"字样，但机会/任务书卡片照常渲染、照常可"批准"，用户很容易把演示当成"AI 已经能干活"。且此前 mock 产出的机会/任务书/经验真实写入了存储（见 P0-3），演示与正式正式数据在同一个列表里混排。

**P0-3 重复对象真实写入（数据 Bug，非渲染 Bug）。**
实证：`youvibe_demo` 库中存在 3 条内容完全相同的增长机会（op_cdb165da / op_3c3211c3 / op_6e149aba）与 3 份相同任务书。根因有三层：
- `create_opportunity`/`create_content_brief` 每次调用生成随机 id 新建记录，无语义幂等；
- 对象缺少"由哪个任务/会话创建"的归属字段，重跑同一目标 = 再写一份；
- UI 把跨会话历史记录全部平铺，不区分本次任务产出。
修复必须在工具层做（字符串级归并 + 语义级由 AI 归并、任务归属字段、按会话过滤视图），不能只在前端隐藏。

**P0-4 AI 输出停留在"泛化文案"，不可执行。**
实证输出："前3秒展示成品，问用户想不想知道怎么做"——没有回答"为什么是这个用户问题/为什么这条内容能带来产品相关用户/预期行动/验证方式"。工具和模型字段其实支持这些（任务书九要素已建模），是 mock 策略和结果呈现层没有把它们组织成"可执行的决策"。

**P1-5 信息架构以数据对象为中心，而非以任务为中心。**
五个卡片列表 = 五张数据库表。用户的心智是"我要完成一件事"，系统呈现的是"这是一堆记录"。工程细节（对象 id、JSON、审计日志）侵入主工作区；而用户最需要的"今天该处理什么"缺失。

## 4. 哪些是 Mock 造成的假象

- "AI 输出了策划结果"——实际是固定脚本按真实工具输出填空。真实模型的意图理解、路径选择、拒绝能力全部未验证（无 Key，持续阻塞）。
- "系统已会复盘学习"——mock 复盘写入的经验已按 Phase 3.6 标记为 mock 并退出正式检索，但**演示库中的机会/任务书没有 data_nature 标记**，仍会被 UI 当正式对象展示。

## 5. 可直接复用的旧系统能力（不要推倒）

| 能力 | 复用方式 |
|---|---|
| Orchestrator 循环/预算/取消/会话持久化 | 原样复用 |
| 工具注册表 + L1/L2/L3 权限 + 审计 | 原样复用，Stage B 只加新工具和小修 |
| store 原子写/产品隔离/导入批次溯源 | 原样复用 |
| 任务书九要素模型 + 人工审批端点 | 原样复用 |
| review_experiments 事实分层 + Unknown 纪律 | 原样复用 |
| build_session_summary（掌握/缺口/待人工） | 直接作为新工作台"AI 状态"数据源 |
| evidence 完整性校验 evaluate.py | 作为质量门 |

## 6. Agent 编排必须改的点（Stage B）

1. **意图分类前置**：规划前先让模型把目标归类为 user_research / content_plan / review / asset_query / general，不同意图挂不同的系统提示词与工具白名单（user_research 不暴露 create_content_brief）。
2. **任务级归属**：创建类工具的入参加 `task_id`（=session_id），视图按任务过滤。
3. **幂等**：create 前先按（product, problem 归一化）查重；重复时返回已有对象 id 而非新建。语义归并允许 AI 辅助，但保留原始证据边界。
4. **user_research 输出结构**：新增 UserSegmentReport 结构（用户群体/需求/证据/平台场景/匹配度/触达方式/假设标注），与机会区分。
5. **连续对话**：会话增加 parent_session 引用与任务状态摘要（≤500 token），用户"只保留第一个"= 对既有对象的状态更新，不是新任务。
