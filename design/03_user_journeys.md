# 交付 C：三个核心业务场景的完整用户旅程

约定：「现有工具」指 Phase 0–3.6 已实现的工具；「新增」指 Stage B 需要补的最小能力。

---

## 场景 A：寻找潜在用户

**用户输入**："帮我找到 YouVibe 的潜在用户。"

**AI 如何理解**：意图分类（新增）→ `user_research`。不走内容策划路径，不暴露 create_content_brief。

**AI 工作路径**：
1. 读 Product Profile（现有：get_product，经 query_* 已可得）。
2. 看数据清单：`build_session_summary` 的 data_inventory → 发现 225 条信号、0 素材、attribution=none。
3. `query_signals` 取回需求文本 → 语义聚类（真实模型职责；规则只做初筛）。
4. 对每个用户群体：需求是什么、出现频次与证据引用、聚集平台（信号 source_platform）、与 YouVibe 价值点的匹配度（对照 value_props，逐条给"匹配/弱匹配/不匹配+理由"）。
5. 触达方式：只用合规路径——目标用户聚集的内容场景做内容获客（对应已有分发账号），**明确排除私信骚扰/KOL 合作**（profile 红线）。
6. 标注不确定性：哪些是证据支持的画像、哪些是假设。

**缺数据怎么办**：如果信号与产品价值点普遍弱匹配（当前真实数据正是如此——信号偏"笔记整理/工具对比"），AI 应输出"当前代理数据不足以证明这批用户是 YouVibe 的潜在用户"，并列出该补什么（YouVibe 目标场景视频的评论、站内问卷）。

**最终交付物**（新增 UserSegmentReport 结构）：
潜在用户研究报告卡片：
- 群体 A/B/C：核心需求、证据引用（可点开看原文出处）、平台场景、产品匹配度（matched/weak/mismatch + 理由）、建议触达方式、确定性标注（fact/inference/hypothesis）。
- 明确"不建议把 X 类用户当作目标"的否定结论（允许）。

**人工节点**：无强制审批（纯研究产出）。用户可【采纳群体→转内容策划】或【标记假设错误→写入反馈】。

**回流**：采纳 → 生成 growth 项目并进入场景 B；反馈 → LearningRecord(human_feedback)。

## 场景 B：制定内容增长计划

**用户输入**："帮我规划 YouVibe 下一周最值得做的内容。"

**AI 如何理解**：意图 = `content_plan`。目标是获客而非播放量（系统提示词已强调）。

**AI 工作路径**：
1. `recall_learnings`（默认排除 mock）→ 有没有已验证/被否定的经验。
2. `query_signals` 需求 → 频次+证据。
3. `query_assets` + `match_assets_to_needs` → 每个需求：有可承接素材（asset_ready）/ 需制作（demand_first）/ 不值得做（reject）。
4. `review_experiments`（有实验时）→ 历史哪种类型导流效率高，用于排优先级。
5. 每个保留的机会给完整九要素判断；**asset_ready → 任务书草稿**（现有工具，授权校验在工具层强制）；**demand_first → 待制作需求卡**（production_need，不装成可发布）。
6. 给出 1–3 个，允许只给 1 个，允许全否。专门校验："播放量高但与产品关联弱 → 不建议"。

**人工节点**：任务书【批准/拒绝+理由】→ 批准后【建立实验】（工具层强制顺序）。待制作卡【排入制作】。

**最终交付物**：一周内容计划卡（每卡：用户问题/主题/切入角度/理由/素材/结构/渠道/到站理由/验证指标/难度工时）+ 每卡的验证方案。

**回流**：批准建实验 → 执行中；发布后人工回填指标（场景 C）。

## 场景 C：增长效果复盘

**用户输入**："上周的视频有播放量但没带来用户，为什么？"

**AI 工作路径**：
1. `review_experiments`：代码层事实——分层指标、Unknown 清单、visit_per_view、小样本标记、归因警告。
2. 对照实验假设：判断是【内容-受众错配】还是【导流路径断裂】还是【数据不可判】——区分"可证实结论"与"不足以验证的假设"，播放高+到站低 ≠ 因果结论（比较渠道/发布时间/样本差异，comparison_notes 已建模）。
3. 不以播放量或单一导流率定生死；样本不足 → 建议小规模复测而不是加大投入。
4. `record_learning` 写经验（真实会话 data_nature=real）。
5. 输出下一轮实验计划（继续/调整/停止，各带理由）。

**人工节点**：无。用户可对结论【有异议→写人工反馈】。

**回流**：经验进入下轮 `recall_learnings`；新实验建议进入场景 B。
