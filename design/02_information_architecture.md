# 交付 B：新产品信息架构

## 一级导航（4 个业务区 + 1 个技术区）

```
┌─────────────────────────────────────────────┐
│ AI Growth Engine        [产品▾] [模式: 正式/DEMO] │
├──────────┬──────────────────────────────────┤
│ 工作台    │  （主区域随导航切换）                 │
│ 增长项目  │                                   │
│ 素材与知识│                                   │
│ 增长复盘  │                                   │
│ 设置与调试│  （技术信息全部收纳在此）              │
└──────────┴──────────────────────────────────┘
```

### 1. 工作台（默认首页）——"提出目标，拿到可执行结果"
- 顶部：产品选择 + 数据模式徽章（正式=真实数据；DEMO=演示，黄色横幅常驻）。
- 核心：自然语言任务输入 + 4 个快捷任务（找潜在用户/规划内容/分析需求/复盘）。
- 运行中：人话进度时间线（"正在分析需求…发现3类需求…缺少到站数据"），可展开的工具明细；模型名/状态/耗时/成本/停止。
- 结果：结构化卡片（不是长文本）——本次任务的机会卡/用户画像卡/复盘结论卡，每张卡带【采纳】【拒绝】【追问】。
- "今天最值得处理的 3 件事"：由真实状态推导（待批准草稿、有实验无指标、数据缺口），缺数据时显示真实阻塞项，绝不伪造。

### 2. 增长项目——"持续推进同一件事"
- 项目 = 一个增长目标（如"YouVibe 十月站外拉新"），聚合其下所有任务会话、机会、任务书、实验、结果。
- 列表按阶段显示：研究中 → 待审批 → 执行中 → 已复盘。
- 点进项目可继续对话：用户说"只保留第一个方向"，系统更新对象状态而非新建。

### 3. 素材与知识——辅助库（不是主操作入口）
- 素材（含授权状态醒目色）、需求信号（含来源批次）、已验证经验（mock/demo 过滤）、产品档案。
- 支持 CSV/JSON 导入。

### 4. 增长复盘——"看结果，不看图表秀"
- 实验列表 + 指标表（传播/导流/产品分层，Unknown 如实显示，归因警告横幅）。
- AI 复盘入口。无数据时只显示"还没有实验数据"+ 如何补齐，不画空图表。

### 5. 设置与调试——技术信息收容所
- 模型连接（Key 输入、连接测试、工具调用兼容性检测结果）、数据模式切换、预算、工具权限说明、审计日志、会话调试。

## AI 与人工职责边界（常驻页面底部横幅，不再藏）

| AI 自主 | 人工必须 |
|---|---|
| 研究、聚类、匹配、起草、复盘、登记 | 批准任务书、发布、授权素材、填写真实指标、连接模型 Key |

## 业务对象与任务的关联

任务（会话）是顶层容器：机会/任务书/用户画像都挂在任务下；实验挂在已批准任务书下；指标挂在实验下；经验经"复盘任务"产出。UI 任何列表都标"由哪个任务产生"。
